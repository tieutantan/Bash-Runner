# Agent Instructions

## Project overview

Bash Runner is a macOS app built with Wails v2. The backend is Go, and the UI is plain HTML, CSS, and JavaScript. It runs `.sh` files with one click.

- `main.go`: Wails setup (window size, title bar, embedded `frontend/` assets, bound `App`).
- `app.go`: all app logic. The exported methods on `App` are callable from the frontend.
- `frontend/`: `index.html`, `style.css`, `app.js`. There is no npm, bundler, or framework.
- `frontend/wailsjs/`: generated by Wails and git-ignored. Do not edit it by hand.
- `build.sh`: packages the app as `Bash Runner.app` in the project root.
- `bash-files/`: sample scripts. Do not run them to test changes, because they can change system state.
- `build/` and `wails.json`: packaging config. Changes here also affect the built app.

## Code conventions

- Write code comments and UI text in English.
- Match the style of the surrounding code: naming, comment density, and idioms.
- Keep the frontend dependency-free. Do not add npm packages or a build step unless the user asks.
- For frontend changes, reuse the existing CSS and component patterns in `style.css` and `app.js`.
- Do not add tests or test tooling unless the user asks. Verification is the build (see below) plus checking the app.

## Build after code changes

After any change to `main.go`, `app.go`, `go.mod`, `icon.png`, `wails.json`, `build/`, or anything in `frontend/`, rebuild the app without waiting to be asked:

```bash
./build.sh
```

This regenerates `Bash Runner.app` in the project root and reopens it. The script quits any running copy first.

Before reporting a task as done, confirm the build succeeds. If it fails, report the error output instead of saying the change is ready.

## Git

- Commit or push only when the user asks.
